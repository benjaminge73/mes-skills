# Liste d'enquête d'un plan

Qui la joue : l'enquêteur (`agents/enqueteur.md`), sur le dépôt, avant que le plan s'écrive ; sur un plan natif, avant `ExitPlanMode` (`avant-le-plan.md`). Le fichier se garde non coché. L'enquêteur recopie la liste, case par case, en tête de sa fiche : une case cochée `- [x]` porte « — preuve : » suivi de la forme de preuve de sa ligne ; une case qui ne s'applique pas dit `sans objet : <raison>`, une case non jouée dit `non vérifié : <raison>` (sans Bash, par exemple). Une case ne se coche jamais sans preuve.

## Les treize vérifications

- [ ] C0 Objets touchés — lister, en une ligne chacun, les fichiers, fonctions, options, valeurs, crons et commandes que le plan va toucher ou créer ; les cases suivantes se jouent pour ces objets ; preuve : la liste des objets, un par ligne
- [ ] C1 Consommateurs — pour chaque objet touché, chercher son nom dans TOUT le dépôt (code, tests, cron/, config/, scripts/, docs, prompts), pas seulement là où le plan le cite. Lister chaque lecteur ou appelant, et dire s'il est dans le périmètre du brief. ; preuve : la commande de recherche et ses lignes (`fichier:ligne`), ou `0 résultat`
- [ ] C2 Docs et consignes qui le citent — `*.md`, SKILL.md, CLAUDE.md, rules, prompts de cron, runbooks qui citent l'objet ou décrivent son comportement : lesquels deviendront faux après le changement. ; preuve : les fichiers de doc ou de consigne qui citent l'objet, avec `fichier:ligne`, ou `0 résultat`
- [ ] C3 Gardes, CI et règles du dépôt — lire ce qui refuse un changement : script de CI locale, workflows, hooks, fichiers de limites (taille, lignes), garde de version, tests de décompte, règles `.claude/rules/`. Dire quelle règle le changement déclenchera, avec la valeur actuelle mesurée (taille, nombre de lignes, version). ; preuve : la règle lue et la valeur mesurée (taille, lignes, version), avec `fichier:ligne`
- [ ] C4 L'état vivant — ce qui tourne déjà : recopier la fiche du relevé du jour fournie par le pilote dans ton brief (cœur Hermes non commité, unités en échec ou dégradées, crons vivants contre leur miroir, passerelle plus ancienne que le cœur, modules de test absents du venv), telle quelle et citée. Le plan crée-t-il quelque chose qui existe déjà, ou change-t-il quelque chose qui sert en ce moment ? ; preuve : la fiche recopiée, citée, ou `non vérifié : sans Bash` si ton brief n'en porte pas
- [ ] C5 Le brief contre le code — chaque fonction, option, fichier, interface ou comportement que le brief suppose : existe-t-il, et fait-il ce que le brief croit ? Lire la fonction entière, pas la ligne citée. ; preuve : `fichier:ligne` de la fonction lue en entier, et ce qu'elle fait réellement
- [ ] C6 Contrat d'un outil externe — pour chaque outil ou API appelé (CLI, service, bibliothèque, cœur d'un autre logiciel) : où le dépôt documente ou teste sa forme de sortie, ses codes d'erreur, ses limites (doc installée, fixture, test, commentaire). Sinon « non vérifié : contrat non documenté dans le dépôt ». ; preuve : `fichier:ligne` de la doc, du test ou de la fixture, ou `non vérifié : contrat non documenté dans le dépôt`
- [ ] C7 Une valeur à plusieurs endroits — chaque nombre, seuil, nom, chemin ou libellé que le plan change : chercher la valeur littérale partout ; lister chaque point de déclaration. ; preuve : la recherche de la valeur littérale et chaque point de déclaration (`fichier:ligne`)
- [ ] C8 Tests existants — tests des fichiers touchés ET de leurs consommateurs (C1), et ce qu'ils figent (valeurs, formats, compte de lignes). L'enquêteur ne les lance pas : la répétition à blanc s'en charge. ; preuve : les tests trouvés (`fichier:ligne`) et ce qu'ils figent
- [ ] C9 Défauts voisins — dans les fonctions lues, la gestion d'erreur, les bornes, les cas vides ; un défaut réel à côté de ce que le plan touche se note. ; preuve : le défaut vu (`fichier:ligne`), ou `aucun défaut vu dans <fonctions lues>`
- [ ] C10 Données réelles — tout volume, compte ou taille dont le plan dépend se mesure sur les données du dépôt (compter les fichiers, lignes, entrées) au lieu de s'estimer. ; preuve : la commande de mesure et son résultat chiffré
- [ ] C11 Historique et décisions antérieures — commits, journaux, docs de décision ou d'incident sur ces objets : une raison passée contraint-elle le plan ? Sans Bash, chercher dans `docs/`, CHANGELOG, journaux d'incidents. ; preuve : le commit, le journal ou la doc de décision (`hash` ou `fichier:ligne`), ou `0 résultat`
- [ ] C12 Sécurité — secrets, droits (sudo, permissions), exposition réseau, données personnelles touchés ou voisins. Une ligne `SECURITE · chemin:ligne · motif` de la fiche du relevé du jour est une question d'office à Benjamin : tu la cites ici, sans en faire l'enquête. Cette case garde son enquête avec ou sans ligne `SECURITE` : la ligne s'ajoute, elle ne la remplace pas. Ne recopie jamais la valeur d'un secret : `fichier:ligne` seulement. ; preuve : `fichier:ligne` du secret, du droit ou de l'exposition, jamais la valeur, ou `rien de touché`
